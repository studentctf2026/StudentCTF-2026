## ShellCoder

| Событие | Название | Категория |
| :------ | ---- | ---- |
| StudentCTF 2026 | ShellCoder | pwn |

### Описание

>Две новости. Хорошая - шелкод можно запускать абсолютно легально. Плохая - доступно лишь несколько сисколов
### Решение

Таск представляет из себя сервис позволящий запускать шелкод на сервере. Но доступные действия ограничены песочницей, которую надо обойти.

Уязвимость заключается в race condition при работе с глобальной переменной g_policy.max_size. Размер shellcode сначала проверяется на допустимое значение 0x100, однако после длительной операции prepare_execution_context() он считывается из глобальной переменной повторно. За это время другой клиент может изменить g_policy.max_size на 0x400. В результате проверка проходит с безопасным размером, а recv() уже использует увеличенное значение и записывает до 0x400 байт в буфер размером 0x100, что приводит к stack-based buffer overflow и позволяет получить управление выполнением через ROP.

В итоге выстраивается следующая цепочка эксплуатации уязвимости:

1) Создаются два подключения к серверу: A и B.
2) A отправляет размер 0x100, проходит проверку и входит в длительный prepare_execution_context().
3) Пока A находится в prepare_execution_context(), B отправляет размер 0x400.
4) g_policy.max_size становится 0x400. B получает Shellcode is too large, но значение глобальной переменной не восстанавливается.
5) A завершает prepare_execution_context() и выполняет recv() уже с g_policy.max_size == 0x400.
6) В буфер размером 0x100 записывается до 0x400 байт, что вызывает stack buffer overflow.
7) Перезаписывается сохранённый RIP, после чего управление передаётся на ROP-цепочку.

8) ROP вызывает update_policy(0x100, 0), устанавливая:
    ```
    g_policy.max_size = 0x100
    g_sandbox_disabled = 1
    ```
9) A завершается, а B продолжает работу с сервером.
10) B загружает обычный shellcode размером ≤ 0x100.
11) B выбирает Run shellcode. Поскольку g_sandbox_disabled == 1, seccomp не устанавливается.
12) Shellcode выполняется с возможностью использовать запрещённые sandbox syscall'ы.
13) shell

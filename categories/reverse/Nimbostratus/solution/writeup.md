Извлечение ресурсов, сборку кандидатов DLL и починку UPX-маркера делает готовый скрипт
Все 128 `PAIR` имеют одну XOR-разность между двумя plaintext-блоками: `Delta = 0x7FFFFFFFFFFFFFFE`.

Правильный порядок частей — `7331 + 2843 + 9157 + 5629`, суммарный размер `2634279 = 0x283227` (это значение дополнительно сверяется внутри SFX). Начало собранного файла:

Заголовки и имена не шифруются, поэтому список файлов виден статически. Из всех `4! = 24` перестановок разобрать все 52 записи и завершить парсинг ровно на конце файла позволяет только порядок `7331, 2843, 9157, 5629`. Контейнер содержит `1 × Flag.txt` и `51 × PNG`, среди которых `Flag_countries_1950/Flags/Student_CTF_Flag.png`.

Правильный порядок — `3179 + 4597 + 6211`: у него PE export directory остаётся корректной (`Nimbus.dll`, ordinal base 1, ровно один экспорт без имени). У порядка `3179 + 6211 + 4597` export directory превращается в мусор — независимое подтверждение.

Готовые файлы лежат в `artifacts/`: правильный кандидат, неправильный (для сравнения) и уже распакованная `Nimbus_unpacked.dll`.
После распаковки открываем `Nimbus_unpacked.dll` в IDA. Экспорт по ordinal 1 (`NimbusVerify`) имеет ABI:

Пароль — 32 hex-символа (128-битный master key). Ресурс `8461` содержит `PAIR` и `VERIFY`; последние используются для финальной проверки найденного ключа.

Для всех 128 пар выполняется `P_left XOR P_right = Delta`, `Delta = 0x7FFFFFFFFFFFFFFE`. Для подходящей пары после раунда справедливо:
`Delta` содержит ровно один множитель `2`, поэтому делим сравнение на два и решаем по модулю `2^63` — теряется старший бит множителя. В раунде используется `K | 1`, значит младший бит `K` тоже неразличим. Для каждого multiplier остаётся четыре кандидата (MSB 0/1 × LSB 0/1).

Алгоритм: набрать multiplier с максимумом голосов → получить четыре кандидата round key → откатить раунд на всех 128 парах → повторить для предыдущего раунда → после пяти откатов потребовать точного возврата ко всем исходным plaintext → проверить результат на 10 векторах `VERIFY`.

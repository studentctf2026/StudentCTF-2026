## Ouroboros
| Событие | Название | Категория |
| :------ | ---- | ---- |
| StudentCTF | Ouroboros | reverse-crypto |

  
### Описание


>Мы перехватили бинарник, который, по слухам, содержит зашифрованный флаг. Внутри — самодельная виртуальная машина, монтгомери-арифметика на больших числах и несколько слоёв шифрования. Разработчик явно не хотел, чтобы флаг достался просто так.

### Решение
В `.data` лежат четыре массива с бессмысленными именами:

| Символ | Размер | Что это |
|---|---|---|
| `d0` | 128 | зашифрованный байткод виртуальной машины |
| `d1` | 80 | модуль `p`, little-endian |
| `d2` | 80 | целевое значение аккумулятора |
| `d3` | 64 | шифртекст с флагом |

В `main` видно четыре характерных блока: SHA-256, ChaCha20, монтгомери-арифметика на десяти 64-битных лимбах и интерпретатор с `switch` на 15 веток.

Первое, что бросается в глаза:

```c
sha256(__executable_start, __etext - __executable_start, tk);
chxor(tk, d0, bc, BCLEN);
```

Байткод расшифровывается ключом, равным SHA-256 от собственного текстового сегмента. Практические следствия:

- любой software breakpoint (`0xCC`) внутри `[__executable_start, __etext)` меняет хеш, байткод превращается в мусор, интерпретатор молча выходит по `default`;
- патчить проверку бесполезно по той же причине;
- отлаживать можно только hardware breakpoints, либо эмуляцией (Unicorn, qiling), либо восстановив логику статически.

# VM
Инструкция — ровно 8 байт: `op(1) a(1) b(1) c(1) imm(4, LE)`. Опкод не совпадает с номером ветки `switch`: используется таблица `OP[32]`, которая строится в рантайме функцией `mkperm` — перемешивание Фишера–Йейтса, засеянное потоком ChaCha20 от `SHA-256(d1)`, то есть от модуля `p`. Ничего секретного тут нет, но статический дизассемблер байткода придётся писать самому.

Расшифрованный байткод — 16 инструкций:

```
00  SETW  W0, 0
01  SETW  W4, 128
02  ONE   B0
03  BIT   W1, W0
04  IDX   W2, W0, W1
05  LDC   B1, W2
06  MUL   B0, B0, B1
07  INC   W0, 1
08  JNE   W0, W4, 03
09  LDT   B2
0a  EQ    W3, B0, B2
0b  JEQZ  W3, 0e
0c  OUT
0d  HALT
0e  DENY
0f  HALT
```

Регистров два вида: восемь 64-битных `W` и восемь больших чисел `B` (640 бит, представление Монтгомери по модулю `p`).

Смысл:

```
acc = 1
for i in 0..127:
    b = bit_i(key)
    acc = acc * CT[2*i + b] mod p
if acc == target:
    print(ChaCha20(d3, key = SHA-256(acc)))
else:
    print("denied")
```

Ветвления по секретному биту нет: бит используется как индекс в таблице констант. Трассировка не даёт ничего сверх того, что игрок и так знает про свой ввод.

Массива `CT` в файле нет. Он строится так:

```
bh     = SHA-256(расшифрованный байткод)
stream = ChaCha20-keystream(bh, 256 * 75)
CT[i]  = int_le(stream[75*i : 75*i+75])  mod p
```

Двойная завязка: константы зависят от байткода, байткод зашифрован хешем кода. Любая правка чего угодно ломает всё сразу. Дампить их из памяти можно, но проще воспроизвести статически.

Обозначим `M[i][b] = CT[2*i + b]`.

Таким образом известны: `p`, `target`, все 256 констант. Нужно найти биты `b_0..b_127` такие, что

$$\prod_{i=0}^{127} M[i][b_i] \equiv \text{target} \pmod p$$

Убираем нулевую ветку. Пусть

$$c_i = M[i][1] \cdot M[i][0]^{-1} \bmod p, \qquad T = \text{target}\cdot\Big(\prod_i M[i][0]\Big)^{-1} \bmod p$$

Тогда задача — subset product:

$$\prod_{i} c_i^{\,b_i} \equiv T \pmod p$$

Полный перебор — `2^128`. Meet-in-the-middle — `2^64` времени и памяти. Ни то, ни другое не проходит. Здесь большинство и застревает.

Смотрим на `p`. Это 600-битное простое, и

$$p - 1 = 2 \cdot q_1 \cdot q_2 \cdots q_{25}$$

где все `q_i` различны и не больше 32 бит. Факторизуется ро-методом Полларда за секунды: 26 простых множителей, максимум 32 бита.

Гладкий порядок группы означает, что дискретный логарифм в `Z_p^*` берётся Полигом–Хеллманом. Для каждой подгруппы порядка `q` таблица baby-step считается один раз и переиспользуется для всех 129 элементов, так что суммарно это десятки секунд на чистом Python.

Берём генератор `g` (проверка `g^((p-1)/q) != 1` для всех `q`) и вычисляем

$$e_i = \log_g c_i, \qquad E = \log_g T \pmod{n},\quad n = p-1$$

Мультипликативная задача превращается в аддитивную:

$$\sum_{i=0}^{127} b_i e_i \equiv E \pmod n$$

Плотность

$$d = \frac{128}{\log_2 n} = \frac{128}{600} \approx 0{,}213$$

Это сильно ниже порога Лагариаса–Одлыжко (0,9408), значит решение единственно и восстанавливается LLL.

Используем вариант CJLOSS. Строим базис размерности 130 (столбцы: 128 «битовых», один модульный, один маркерный), `N = 2^90`:

```
row i (0..127) :  A[i][i]   = 2
                  A[i][128] = N * e_i

row 128        :  A[128][128] = N * n

row 129        :  A[129][j]   = 1   для j = 0..127
                  A[129][128] = N * E
                  A[129][129] = 1
```

Комбинация `Σ x_i·row_i + k·row_128 − row_129` даёт вектор

$$(2x_0-1,\ \dots,\ 2x_{127}-1,\ 0,\ -1)$$

норма `sqrt(129)` — исключительно короткий вектор в решётке с определителем порядка `2^690`. LLL находит его сразу.

Из выданной строки: если последняя координата `-1`, то `b_i = (v_i + 1)/2`; если `+1` (вектор с обратным знаком), то `b_i = (1 - v_i)/2`.

Собираем ключ `key = Σ b_i · 2^i`, проверяем `∏ M[i][b_i] == target`, считаем `SHA-256` от 80-байтового little-endian представления `acc`, расшифровываем `d3` ChaCha20 с нулевым nonce.
